# App 与 OpenAI 桥的交付验收门槛

这八项是交付条件，不是可选优化。源码和隔离候选已验证，用户另外报告本地手工桥试用在退出重开 App 后可继续使用；**尚无一套通过全部八项、可交给用户升级现用环境的正式签名配套包**。

## 验收矩阵

| 编号 | 场景 | 必须达到的结果 | 最终验收方法 |
|---|---|---|---|
| A1 | 桥完全没运行，新建会话 | 自动启动，等待就绪，正常取得回复 | 最终安装版 App 新建会话；事前确认无本实例服务，不预启动、不手调 Hook；首个模型请求前健康就绪 |
| A2 | 桥没运行，恢复旧会话 | 同样正常，不需要手动启动 | 保留测试会话，停止自身测试实例，再从 App 恢复；确认会话 ID 不变、取得回复 |
| A3 | App 更新导致原进程结束 | 更新后第一次需要桥时能恢复 | 测试环境真实更新 App；确认旧服务已结束，再发第一条消息；模拟杀进程只作辅助证据 |
| A4 | 桥意外退出 | 有限度恢复；无法恢复时明确报错，不无限重启 | 杀死自身测试 CCR 验证恢复，再用持续失败夹具验证次数/时间上限、持久故障标记及界面错误；不重复发送模型请求 |
| A5 | 同时打开多个会话 | 只启动一套桥和看护，不争抢端口 | 冷态多会话并发；记录进程身份、单例锁和启动次数，全部等同一次就绪结果 |
| A6 | 停止生成 | 取消请求，不把桥一起弄崩 | 假上游持续流式输出，App 停止后确认上游连接取消、桥仍健康，再次请求成功 |
| A7 | 使用其他接口 | 不误启动、不干扰 | 远端接口、其他回环端口、登录/端侧模式均不调用本桥启动器；不改变其 URL、代理或认证 |
| A8 | 卸载组件 | 不再被钩子或看护拉起；删除真实配置另行确认 | 最终组件卸载后新建/恢复、等待已有看护检查；无新桥；保留配置与历史，清除数据必须独立确认 |

## 证据分级

1. **源码测试**：临时 HOME、假凭据、loopback 假上游，覆盖状态和负面边界。
2. **本地候选归档测试**：验证实际打包文件与源码一致，并从归档安装后重复隔离测试。
3. **正式交付验收**：维护者发布的正式签名 App 与组件，经过签名安装、原生 App 操作和真实更新/卸载。

低一级的证据不能替代高一级。健康检查不能替代模型回复；直接调用 Hook 不能替代 App 操作；连续 502 后靠 CLI 重试成功不算“首请求前就绪”。真实付费请求及现用环境迁移须另获用户确认；所有输出不包含凭据。

## 当前明确阻塞

- 安装版 App 的 streamfix 地址已经是不可解码的 HMAC 通道；现用与旧候选 Hook 都无法由通道号识别本桥。旧可解码包装的测试只保留为历史证据。
- 旧 SessionStart Hook 是异步派发，无法保证发首个请求前就绪。
- App 与桥需要稳定、版本化、不含密钥的受限启动/就绪契约。优先在包装 URL 和启动 CLI **之前**完成检查，不倒退 streamfix 的安全设计，不读取原供应商密钥文件，不把所有自定义接口视作本桥。
- 有限故障恢复、错误呈现、原生 App 验收、签名配套发布与现用手工桥迁移须分别验证，不得笼统标为通过。

## 提交与验证边界

- 配套候选在源仓库及独立 App 工作树开发，自动测试使用隔离假数据。
- 用户另行授权的现用本地试用只适配手工桥，不等同正式组件迁移；其程序文件、配置、日志和会话不随 PR 上传。用户报告退出重开 App 后可用，但没有证明真正冷态或 APK 升级。
- 用户已明确授权提交配套源码/市场 PR；合并和发布仍由维护者按 CI、审查和兼容契约决定，不绕分支保护。
- 本次公开提交不修改/重启现用环境、不切换接口、不读取或索取真实密钥，不改签名根、不伪造 `verified.json`、不覆盖其他工作的未提交文件。
- 正式交付仍须给出兼容版本、安装/迁移步骤、回滚方法、已知限制和八项最终验收记录。
