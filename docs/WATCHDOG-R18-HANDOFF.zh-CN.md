## 修改内容

| 情况 | 新策略 |
| --- | --- |
| 已就绪的同一 PID+启动时刻实例，健康请求暂时失败 | 独立300秒宽限，保留原进程；不修改2秒单次健康请求上限 |
| 桥请求网络失败，独立随机回环端口对照也已监听但不可达 | `LOOPBACK_UNAVAILABLE`，仅等待与复查；不重启、不消耗/清空预算、不宣称健康 |
| 对照可达、服务自身持续故障 | 宽限及连续失败判定后仍走原有限恢复 |
| 对照无法创建、资源错误或结果不可信 | 不据此延期，按普通探活失败处理 |
| 进程确实退出/连续崩溃 | 不套用已就绪实例的300秒宽限，保留原启动/崩溃处理及三次预算 |
| 补丁失败、已有故障标记、停用/卸载/实例变化 | 原保护保持，不自动复活或清故障锁 |
| 长调度空窗 | 重新累计连续健康/失败样本，不清持久重试预算 |

关键实现是运行源码默认值，不依赖上一次终端 export。正式更新经既有受管升级路径部署后，重开看护仍采用新策略。**当前线上实例没有替换；它仍使用先前用户确认的临时300秒启动参数。**
